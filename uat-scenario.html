02Role Resolution & RBAC

mpp_admin / asset / procurement_manager / procurement_officer come from Entra App Roles. The approval chain (user_manager / user_vp / user_svp) and the focal point (user) are derived from plan data — a logged-in user whose email is named on a plan as owner / manager / VP / SVP picks up the matching role automatically (most senior wins). No in-app switcher.

IDTest case Role / actor Priority Result
ROLE-02 Each Entra-assigned role resolves to the correct UI
  1. For mpp_admin / asset / procurement_manager / procurement_officer: assign the App Role in the Enterprise Application.
  2. Sign in; check sidebar nav, home view, persona chip, and FORWARD/BACK button labels.
Expected: Asset → "Asset Review" queue; Proc Mgr → "PM Assign / PM Review" queues; Proc Officer → "Officer Review" inbox; Admin → tabbed dashboard of all gates. (Manager/VP/SVP are covered by ROLE-05 — they no longer require an Entra App Role.)
 Admin / Asset / PM / Officer Must Pass / Fail
ROLE-05 Approver chain (Manager / VP / SVP) is derived from plan data — no Entra App Role needed
  1. Pick a PTTEP account that has no MPP App Role assigned in the Enterprise Application.
  2. As any Focal Point, create a plan that names this account's email as approverEmail / approverVpEmail / approverSvpEmail (any of the three).
  3. Sign in as the test account.
Expected: The user lands on the Approver "Inbox" view immediately (no sign-out cycle, no Enterprise Application change). The plan appears in their inbox; /api/mpp/whoami reports resolvedFrom: "derived" with derivedMatch set to the most senior tier on which the email appears (SVP > VP > Manager > Owner). Approve/Reject actions on the matching gate work end-to-end.
 Manager / VP / SVP · no App Role Must Pass / Fail
